# Демонстрационная CRM на Render

Эта папка содержит код и согласованную копию справочников. Клиенты, поставщики, рабочие сотрудники, партнёры, реквизиты компании, пароли, фото и документы не перенесены. Пользователи и примеры заказов — вымышленные.

## 1. GitHub
1. Откройте GitHub Desktop и войдите в свой GitHub.
2. File → Add local repository → выберите эту папку Render-demo. Если GitHub Desktop предложит создать репозиторий здесь, выберите Create a Repository.
3. Если не было коммита: в Summary напишите «Демонстрационная CRM» и нажмите Commit to main.
4. Publish repository: название curtain-crm-demo, флажок Keep this code private оставить включённым. Нажмите Publish repository.

## 2. Render
1. В Render нажмите New → Blueprint (новый отдельный сервис; BR_photo не меняйте).
2. Выберите репозиторий curtain-crm-demo. Если его не видно, дайте интеграции Render доступ только к этому репозиторию.
3. Render прочитает render.yaml. Проверьте: один Web Service curtain-crm-demo, Docker, Free, без базы данных и без платного диска.
4. В CRM_DEMO_PIN введите свой отдельный ПИН из четырёх цифр. Не помещайте ПИН в GitHub или чат. Это значение задаётся только в Environment Render.
5. Нажмите Deploy Blueprint / Apply и дождитесь статуса Live. Сервис сам соберёт интерфейс, создаст временную базу и примеры.
6. Откройте HTTPS-ссылку сервиса вида https://curtain-crm-demo-....onrender.com/#orders.

Секрет Django генерируется автоматически. Build Command и Start Command вручную не нужны: используется Dockerfile.

## Вход
Имя пользователя | Роль
--- | ---
demo_owner | Собственник: все справочники, настройки и заказы
demo_designer | Дизайнер: собственные заказы
demo_designer2 | Второй дизайнер: отдельные заказы
demo_cashier | Касса: просмотр всех заказов

ПИН для этих демонстрационных пользователей — значение CRM_DEMO_PIN, которое вы сами ввели в Render.

## Поведение демо
- После потери временного диска справочники восстанавливаются из включённой копии, примеры создаются заново. Простое засыпание не обязательно сбрасывает базу, обновление/пересоздание сервиса может её сбросить.
- Изменения предназначены только для обсуждения. Не вводите реальные персональные данные и не используйте демо для рабочего учёта.
- Первый запрос после простоя может ждать запуска сервиса.
- Бесплатные часы Render общие для сервисов workspace: существующий бот и CRM расходуют одну квоту. Если сервисы активно работают одновременно, бесплатной квоты может не хватить на весь месяц.
- Учётки и примеры создаются автоматически; сброс не переносит изменения назад в локальную CRM.
- Фото и вложения технически доступны, но хранятся временно и для показа не нужны.

## Обновление
После дальнейшей разработки запускается deploy/render/prepare_upload.py из основного проекта. Он обновляет исходники в Render-demo, сохраняя .git. Затем в GitHub Desktop: Commit → Push origin. Render получает новый код; данные демо могут сброситься.

## Если не запустилось
Откройте Render → сервис curtain-crm-demo → Logs. При ошибке отправьте текст ошибки, скрыв значения переменных, ПИН и ключи. Не меняйте настройки работающего BR_photo.

## Обновление копии справочников
В основном проекте export_demo_references.py экспортирует только согласованные справочники, без клиентов, поставщиков, сотрудников, партнёров и реквизитов. Поставщик в товарах и формулах очищается. При смене копии временная демо-база пересоздаётся; обычный перезапуск с прежней копией сохраняет изменения. Рабочая база не изменяется.
